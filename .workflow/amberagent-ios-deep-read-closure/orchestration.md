# Orchestration: AmberAgent iOS Deep Read Closure

## Execution Rules

- Keep the original objective intact.
- Ask for approval before risky, expensive, external, or destructive actions.
- Keep immediate blocking work local.
- Delegate only bounded, disjoint, materially useful packets.
- Integrate packet results before final verification.

## Branching Rules
- If a source lane needs real credentials, paid API, account state, or a security-scoped file unavailable locally, implement a mockable adapter or honest unsupported state and continue other lanes.
- If WebKit/WebMount or file permission blocks twice, stop retrying that lane and record exact unsupported behavior.
- If an edit would require Android business logic changes, Xcode project generation changes, entitlements, or private config, pause before doing it.

## Packet Prompts
- Android explorer: read Android Deep Read UI, impl, templates, tools, board repository/signals/agent; summarize capabilities and iOS-relevant gaps without editing.
- iOS explorer: read iOS Board, settings, persistence, shell, chat, search, conversation, document, web mount, tests; summarize reusable seams and risks without editing.

## Completion Audit
- Gap Matrix exists and informed implementation.
- Deep Read is accessible and locally functional on iOS.
- P0 local source lanes are tested or explicitly blocked with reproducible errors.
- Final verification commands and results are captured.
