2. **P2 — NS4 shared slug repair drops the character-card file extension.** `NovelWorkspaceSlug.reservedPath:51-53` now falls back when leaf is dot-leading. The one non-migration production consumer, `NovelMarkdownWorkspaceViewModel.proposeCharacter:985-989`, passes `slug(name)+".md"` and fallback `character`. A valid dot-leading character name therefore produces `setting/characters/character`, without `.md`. Character prompt requires that exact path (`NovelWorkspacePrompts.kt:268,290`); free writes accept the setting prefix, but `NovelWorkspaceStore.collect:141` only includes md/yaml, so the card does not enter catalog/fileTree/export. Migration callers add .md after allocation and are correct. Minimal fix is the character allocation boundary with a regression for target extension, visibility and ordinary collision behavior. Root notified; no speculative generalized path framework requested.

Both are closed by the follow-up source review below. The initial descriptions are retained as review evidence.
