# Packet C7 — Durable 润色、后台执行、通知与深链

## Objective

把旧的页面内存批量润色替换为同一 workspace job store 内的 durable batch：冻结连续章节范围与
上下文来源，复用 Chat provider 和只读工具，经过候选、独立审稿、最多两次定向重写后原子替换正文；
离页、进程回收或系统执行窗口结束后仍从 checkpoint 继续，且通知点击直达对应工作区作业。

## Ownership

- 主 agent：联合 job store、repository 原子提交、creation/Entry/ArkUI 集成、官方 API 核对、真机验收。
- `c7_android_polish_audit2` / `c7_job_seam_audit`：Android 固定参考与 C6 复用边界只读审计。
- `c7_harmony_platform_audit` / `c7_polish_ui_audit`：WorkScheduler/通知/深链和 UI 只读审计。
- `c7_polish_domain`：纯领域与聚焦测试窄切片。
- `c7_final_logic_gate` / `c7_final_ui_gate`：完成后的调用链、持久语义和真机 UI gate。
- `c7_process_lock_research`：API 12 跨进程单写者边界与 public caller 覆盖复核。

## Invariants

- `.amber/jobs.json` 是 ghostwrite 与 polish 的唯一联合作业集合；同 project/branch 只有一个非终结 job。
- 润色启动冻结连续 ordinal 范围、chapter id/title/content digest、branch/CAS、model policy 与四类上下文来源；
  runner 不重新读取漂移后的原文冒充冻结输入。
- candidate/review 都绑定 job/chapter/source/candidate digest；writing/review 职责精确选择，工具 profile 只读；
  最多两次定向重写。
- 通过审核后 repository 在一次 workspace root swap 内写润色前版本、目标正文、ledger/undo/receipt、
  checkout 和 job cursor；旧 owner、旧 epoch、旧 CAS、改过的原文均不可提交。
- 页面离开只停止轮询；pause/cancel 先持久化并旋转 owner，再 abort 真实 Chat request。
- WorkSchedulerExtensionAbility 仅 claim/推进同一 job。系统 2 分钟窗口不足时写 `waiting_system` checkpoint，
  不伪报完成；旧 callback 永久失去写权。
- 通知使用稳定 job id 覆盖更新，Want 携 `projectId/branchId/jobId`；Entry 与根页校验、消费并直达正文作业卡。
- 不修改或提交用户已有的 `NovelBatchPolishSheet.ets` 脏改；C7 新建 durable sheet/card，C8 仅移除旧 caller。

## Verification

- domain/repository/runner/creation 聚焦测试覆盖 range、context、互斥、claim、rewrite、原子提交、部分失败、
  pause/resume/retry/cancel/cold recovery 与后台 yield。
- DeepRead 与 Chat 全域回归，改动 ArkTS lint，AGC 构建和指定真机覆盖安装。
- 真机截图复核新建任务 sheet、正文作业卡、禁用态、长失败文案与通知深链；官方 `hidumper` 触发
  WorkScheduler 回调并核对 durable checkpoint。
