## Implemented seams

- `createRunToolCatalog(RunToolCatalogDeps)` mechanically shares the existing primitive registry → Recipe/Plugin validation/tools → final registry/introspection/search chain. Its `baseTools`, `tools`, `recipeAdapter` and `pluginAdapter` always use the same primitive oracle. `scopeRunTools` preserves approval flags, package envelopes and `mcpTarget` while binding activity to the real conversation ID. Ordinary Chat appends its existing subagent tools outside this module.
- `createCouncilSeatLoop(deps,conversation,store,makeProviderForStep,toolPromptModel,mode,beforeEffect?)` accepts C's actual fixed provider/model and durable seat store. It imports no AppContainer, ChatRuntime or DetachedConversationContext. Latest context/history reads call that same store's `load`; absent saved conversation is an error, never an initial-snapshot fallback. Compact tools use C's supplied provider plus real compact store/prompt.
- FULL uses the existing full profile within the frozen Assistant/available scope, as the final root assembly contract specifies. It does not change the stored Assistant's Chat profile or turn on either auto-approval setting. SEARCH exposes strictly the four original search primitives and requires both original and current web-search consent; it adds no packages/discovery tools.
- Local options, enabled skills and MCP server IDs are intersected with that same Assistant's current configuration. A missing or different Assistant throws before any primitive/remaining factory/catalog is called. Current feature and approval revocations can shrink the original scope, never enable an originally absent option. Missing visible-seat hosts (`wm_*`, `webview_*`, `javascript_execute`, queue, deep-read navigation and parent-Chat subagents) are excluded before package validation/discovery. Real native runtimes, artifacts, memory, skills, HTTP Feishu/image tools, session/context and injected service factories remain available when their real dependencies and gates permit them.
- Initial real MCP wrapper aliases and `mcpTarget` identities remain fixed; live scope only filters the corresponding targets. MCP management reads are restricted to the same servers/targets. Generic `mcp_call_tool` resolves a unique allowed identity, captures it in `council_mcp_target` before approval/checkpoint persistence, and rechecks that saved identity against current availability before executing with an explicit server ID. Changing a server name or removing a same-named peer cannot redirect that call.
- The actual dispatcher retains default hooks and the original fixed SSH/Mosh terminal guard. Its final before hook rechecks current primitive availability and the existing permission resolver against the intersection of original/current approval flags, then awaits C's same-store effect barrier. Real barrier IO errors are wrapped in the root's explicit `ToolInvocationBarrierError`; no fake cancellation, side-effect fallback or second tool engine is introduced. Recipe/Plugin retain their original saved-child STARTED barriers.
