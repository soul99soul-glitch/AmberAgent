## Actual implementation

- `GoogleAuthSupport.ets` receives the existing `HttpClient` via `initializeEntryGoogleAuth`; repeated initialization with the same instance does nothing. It exposes the frozen resolver/status/login/retry/logout/catalog APIs, `forgetGoogleProvider`, and the save-success-only `updateGoogleAuthConfiguration`. It has no DI imports or new HTTP implementation.
- `GoogleOAuthClient.ets` uses the domain's single DTO/wire source. Code Assist and Antigravity retain distinct hosts, scopes, metadata, wrappers, token namespaces and catalogs. OAuth client ID/redirect/optional secure client secret come from the saved provider. No copied platform client or secret, fake FREE eligibility, response-derived fallback client, or model catalog guess. Code Assist reports its absent catalog interface and allows manual model IDs through D's existing UI.
- PKCE uses the existing CryptoArchitectureKit CSPRNG and SHA-256 pattern. State/verifier/code remain attempt memory. Redirect validation permits only explicit nonzero `http://127.0.0.1:PORT/PATH` or `http://localhost:PORT/PATH`. The callback compares path, exactly one matching state, and exactly one code/error; wrong path/state/duplicates receive 404/400 without token exchange. Valid callbacks are consumed once, reply finishes, and the native listener/clients are closed before exchange. Native callback errors, 120-second callback timeout and cancellation settle the attempt and close its handle. The whole login/onboard attempt is also bounded.
- Offline official socket documentation and the actual SDK established `TCPSocketServer.close` **since API 20**, despite listen being API 10 and getLocalAddress API 12. Root therefore approved E's small POSIX native helper. B imports its actual `GoogleLoopbackHandle/Request` declarations and awaits `closeGoogleLoopback`; closing a client is never reported as closing the listening port. E's separate real socket evidence is in `E9-native.md`.
- OAuth refresh is one flight per provider+mode. Each waiting conversation has its own `AbortSignalLike`: stopping A rejects A while B keeps the shared request; the last departing waiter cancels that request. Refresh preserves an omitted refresh token and existing project/tier. `invalid_grant` removes the matching secure session.
- Per-identity generation and writeTail checks guard the **actual** secure commit. Logout/relogin/config replacement/delete invalidate old work; already running writes settle before matching removal. Neither a failed secure save nor configured credentials yield READY. A token saved before failed onboarding remains `onboarding_required`, with the server's validation URL and an explicit retry; no model request guesses a project or repeats onboarding automatically.
- `GoogleServiceAccountToken.ets` reads the owned private-key reference or the explicitly permitted legacy field, builds the official JWT claims, calls C's PKCS#8 RS256 signer and uses the actual token form. Cache/singleflight keys follow the credential revision, including the real key digest. There is no OAuth refresh token flow for SA. Vertex ModelGarden uses the verified publisher-models route and actual pagination; repeated page tokens fail precisely.
- Provider deletion invalidates both OAuth runtime modes, closes callbacks and waits their writes, then calls C's provider-owned two-namespace cleanup. It also drops SA memory state. Normal logout removes only its captured binding. If a newer binding owns the same provider+mode, old cleanup is serialized behind its writeTail and the secure store's binding check preserves the new session.

## Actual save and review boundaries

D saves the provider JSON first, then calls the authoritative configuration notification, then performs superseded owned logout/reference cleanup. Post-commit notification/cleanup failure reports that configuration was saved but local auth update/cleanup failed; it does not enter the pre-commit rollback and delete the newly referenced credential.

A/root found an actual E6 seam: a detached conversation's frozen old client could call `state(oldSetting)`, invalidate the new client's authorizing attempt, and restore the old binding. The existing lifecycle group reproduced it (`Missing expected rejection`, `/tmp/e9-google-entry-stale-binding-red.log`). Ordinary status/resolve/retry/catalog now reject a mismatched binding. Only explicit begin or the successful-save notification may replace it. `/tmp/e9-google-entry-stale-binding-green.log` is 1/1 PASS. D's separate old-logout-after-new-login observation is covered by the same group; that was a source-identified fix, not a claimed red reproduction.
