# Amber UI Design

围绕一个明确任务设计界面，交付真实内容和可用操作。遵守当前系统提供的输出协议，不混合不同协议的权限和功能。

## 选择输出

- 静态网页卡片使用一个 `show-widget` 代码块，JSON 包含 `title`、`widget_code`。HTML/CSS 自包含，脚本、外部资源和事件处理不会执行，不放不可操作的假按钮。
- 原生选择、输入、解释操作使用系统定义的 `amber-ui v=1` 协议。只用已有节点和样式 token，状态先声明、父节点先出现，末尾输出 `{"op":"end"}` 并关闭代码块。按钮的 `draft` 动作只填入聊天输入框，不自动执行工具或网络请求。
- 用户明确要求“小应用 / MiniApp / 小程序”时，使用当前系统注入的 MiniApp JSON 协议，完整 HTML 放在 `html`。使用真实内联交互，仅声明实际需要的宿主权限，网络和持久化遵守 Amber bridge。
- 一般交互请求优先判断现有原生智能 UI 是否足够。需要脚本、计时器、完整页面或持久化时，向用户说明需要小应用；不要擅自输出 MiniApp，否则输出转换器可能不接收。
- 鸿蒙的 `full_html` 当前仅有静态预览，不会执行脚本。不要把它当作可运行的交互页面。图表、SVG、3D 使用系统已给出的对应协议，不能把它们塞进原生智能 UI JSON。

静态卡片示例：

```show-widget
{"title":"今日专注","widget_code":"<main style='padding:16px;font-family:system-ui'><h2 style='margin:0 0 12px'>今日专注</h2><p style='font-size:28px;margin:0'>90 分钟</p><p>已完成 3 个专注时段</p></main>"}
```

## 移动布局

- 320px 宽度下换行且不横向溢出，长内容允许纵向滚动；不强行把桌面多栏缩进手机。
- 标题、主要数值、说明、操作有明确层级。相关信息靠近，组与组之间留出空间。
- Web 控件触摸区域至少 44×44 CSS px，原生控件使用宿主尺寸；长中文标签不截断关键含义。图标按钮提供可访问名称，表单有标签，键盘焦点可见。
- 遵循宿主深浅色主题，颜色不作为唯一状态提示。图片指定尺寸或宽高比以减少布局跳动。
- 小应用使用完整 HTML、`lang`、viewport 和系统字体。将适合首屏的主要结果放进唯一的 `<main data-amber-reveal>`；长页面不要为动画强行缩短或隐藏内容。

## 动效与揭示

首次生成后的点阵线框和内容揭示由宿主负责，模型只输出真实成品。不要添加骨架遮罩、假生成进度、Agent 日志、TOK/S 或另一套揭示脚本。

小应用自身交互可用 opacity、transform、颜色等短过渡：按压约 150ms、状态切换约 250ms、较大内容切换约 400ms。支持 `prefers-reduced-motion`，避免无必要循环或动画改变布局高度。原生智能 UI 的动效由宿主提供，不输出 CSS 或自定义动画字段。

## 交付检查

检查输出协议可解析、控件动作真实、权限符合实际调用，内容在窄屏和深浅色下可读。不从 CDN 下载库，不在静态卡片中放可执行脚本，不伪造数据或生成进度。没有用户要求时不扩展网络、系统权限或自动外部操作。
