# Android SSH 多 profile 验证

客户端固定为 `com.github.mwiede:jsch:2.28.7`，由用户明确授权加入。实现复用 TerminalRuntime 的任务、日志、输出上限和取消链路，以及现有 Keystore SecretStore。

## 改动范围

- `feature/terminal/api`：SSH profile、凭据版本引用、主机信任与终端运行时模型。
- `core/settings/ssh/SshProfileStore`：多 profile、默认项、按版本发布凭据、首次信任确认的 CAS；普通设置迁移只清理自身持有的凭据。
- `feature/terminal/SshClient`、`TerminalRuntime`：密码或私钥认证、认证前校验主机指纹、输出脱敏、连接取消和超时；通过 consumer rules 保留 JSch 反射加载的实现。
- `SettingSshProfiles`、`SettingSandboxPage`：新增／编辑／删除 profile、默认选择、主机指纹确认及手动执行命令。
- `TerminalTools`：列出 profile，给现有执行工具添加 `remote_ssh` 和 `ssh_profile_id`；Model Council 的远端路径使用远端 HOME。

## 已验证

96 项定点 JVM 测试全部通过：11 项主机信任、11 项 profile 存储、25 项凭据迁移、8 项客户端单测、8 项真实 SSH 回环测试、8 项终端模型测试及 25 项 Model Council 测试。

真实回环测试运行实际 JSch 客户端，服务器仅监听 127.0.0.1，使用本次生成的 ECDSA 密钥。覆盖首次探测与显式信任、stdout/stderr、退出码 7、错误主机指纹、错误私钥、OpenSSH 格式私钥、加密 PEM 私钥及口令脱敏、超时、关闭连接与多个 profile 的身份隔离。可复现命令（需本机 JDK、sshd、ssh-keygen）：

```sh
python3 scripts/test-ssh-loopback.py
```

`app:assembleDebug` 通过，包含 Native 构建。另用临时 Gradle init script 为 Debug 开启 R8 并禁用映射上传，生成压缩测试包；在只读 Android 35 模拟器中成功执行 `echo r8-ssh-ok`。这验证了代码移除后的客户端路径，不等同于正式 Release 混淆优化的完整验证。

常规 Debug 包在 Android 35 模拟器中保存了两个独立 profile，分别使用 OpenSSH 格式私钥和带口令的加密 PEM 私钥。两者经 Keystore 保存、独立确认服务器指纹后，分别成功执行 `echo android-ssh-ok` 和 `echo profile-b-ok`。第二个 profile 可设为默认，强制重启后两份配置和默认选择均恢复正常；设备偏好文件确认两份配置已持久化，且配置文件及密文文件均无测试私钥／口令明文。表单高度和滚动顺序已修正，加密私钥的口令字段已经过实际滚动和输入验证。非默认 profile 的操作行改为自动换行，避免编辑／删除按钮在窄屏被裁切。模拟器中删除默认 profile B 后，profile A 保留并自动成为默认项。

## 验证边界

- 正式 Release 构建被现有 Firebase 配置门禁阻断，缺少 `app.amber.agent` 对应的 Firebase client；没有绕过此门禁生成正式发布包。
- 回环 sshd 禁用密码登录，因此密码认证未做成功实连验证；未连接个人服务器，也未读取个人 SSH 配置或密码。
- 当前 Android 后端支持 RSA/SHA-2、ECDSA，不支持 Ed25519/Ed448；不提供 PTY、SFTP、远端文件同步或自动重连。
- 关闭连接不代表远端进程已停止，缺少远端退出回执时记录 interrupted/unknown。
- 全仓本地化检查仍有 6 项既存问题（其他语言 key 差异及无关页面硬编码）；本次 SSH 的中英文资源、占位符和 Android 资源合并检查通过。
