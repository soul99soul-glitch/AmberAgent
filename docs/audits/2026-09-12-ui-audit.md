## 0. 执行摘要

### 总体判断

本项目**不缺设计系统**——`AmberTokens`（4 基底 × 5 accent）、`AmberType`（7 级字号）、`AmberPrimitives`（Card/Hairline/BtnInk/BtnAccent/LiveDot/SectionLabel/pressable）是一套意图清晰、注释充分的 token 体系。真正的问题是：**新 token 体系从未完成收敛，旧体系没有退役**——页面层目前同时跑着三套色彩来源、二十余种自造字号、零间距刻度；约一半页面绕过 ViewModel 直接注入 Repository/DAO；最大的 5 个 UI 文件各超过 1900 行且存在 flag 门控的双实现。

### Top 5 关键问题

1. **色彩三轨并存且同屏混用**：52 个页面文件仍走旧 `workspaceColors()`（内含浅色硬编码值，团队自己注释过"在浅色模式硬编码"），25 个走新 `LocalAmberTokens`，12 个文件同一屏幕两套混用，另有 ~28 个文件裸用 `MaterialTheme.colorScheme` 或页面私有调色板。这是"同屏色差/换主题破相"的根因。
2. **间距无刻度**：无 `LocalSpacing` 类 token，横向 gutter 在页面间漂移于 12/14/16/18/20dp，单文件内最多出现 7 种不同横 padding（`CouncilTimelineTab`）。3/5/7/9/11/13/15/17/23dp 等离网值合计数百处。
3. **字号失控**：`AmberType` 只有 7 级刻度，实际代码用了 ~20 种 sp 值（9.5/10/11.5/12.5/14.5/17/19.5/23/24/29/39…），`SessionHomePage` 单文件 21 处裸 `fontSize`，`StatsPage` 热图标签缩到 ≈7.7sp 已低于可读阈值。
4. **巨型页面 + UI 层状态机**：117 个 >120 行 composable；`BackupPage` 单函数 673 行内含 20+ `collectAsState` 与 `restoreInFlight`/`restoreObservedLoading` 双标志握手；`SettingExperimentalOfficeProPage` 直接注入 DAO；`MiniAppRunnerPage` 注入 11 个服务；`SessionHomePage` 把 65 行"开议会房间"业务编排写进 Composable。
5. **双实现并存**：`Markdown.kt`(3625 行) vs `MarkdownNew.kt`(1662 行) 两套渲染器；`ChatPage/DeepReadScreen/Markdown/GenerativeWidgetCard` 各有 `*Split.kt` 实验实现经 `PerfFlags` 编译期开关分发且全部默认关——同一界面两份代码，修复只落一份。

## 2. 系统性问题（按严重度）

### 2.1【Critical】色彩三轨并存，同屏混用

**现象**：页面层三种取色路径并存——

- `workspaceColors()`：52 个页面文件（见附录 A）
- `LocalAmberTokens`：25 个页面文件
- 裸 `MaterialTheme.colorScheme` / 私有调色板：约 28 个文件（`StatsPage`、`MiniAppRunnerPage`、`DebugPage`、`LogPage`、`DeepReadScreen` 的 `magazinePalette` 等）

**混用证据（同文件两套并存）**：`BackupPage`、`BoardPage`、`ChatPage`、`CouncilRoomComposer`、`CouncilRoomPage`、`HistoryPage`、`MiniAppGridCard`、`NovelMarkdownWorkspacePage`、`NovelProjectsPage`、`NovelUi`、`SettingAgentMemoryPage`、`SettingStoragePage` 共 12 个。

- `BoardPage`：`workspaceColors().muted`（L275、L645）与 `LocalAmberTokens.current.ink3`（L675）相邻共存。
- `ChatPage:550` 注释自承："必须用 `LocalChatTheme.current.bg` 而非 `workspaceColors().paper`——后者在浅色模式硬编码"，但同文件 L1105/1153/1225/1923 仍在用 `workspaceColors()`。

**影响**：同一屏相邻两行色阶不同源（`muted` vs `ink3` 浅深不一）→ 用户感知的"这块颜色不对/没对齐感"；Sage 基底、AMOLED、自定义 accent 下只有新 token 路径保证正确；旧体系 `WorkspaceColors` 的 blue/green/amber/red 语义色与新 token 无对应关系，accent 更换完全不生效。

**建议**：见 §5.1-①。

## 5. 重构方案

### 5.1 P0（一周内，收益最大，风险可控）

**① 色彩收敛**
- 将 `workspaceColors()` 标记 `@Deprecated`（或保留 API、内部改为代理到 `LocalAmberTokens` + `MaterialTheme.colorScheme`，先保证行为正确再逐文件迁移）。
- `WorkspaceColors` 的 blue/green/amber/red 语义色无 token 对应项——先在 `AmberTokens` 增补语义色槽位（或新增 `LocalSemanticColors`），再迁移，避免为迁移而删功能。
- 删除 `DeepReadScreen.magazinePalette`，映射到 token；`SubAgentAvatar` 的 39 hex 头像调色板迁入 token/常量层集中管理。
- 验收：全部 62 条路由在 light/dark/sage/sage-dark × 5 accent 下截图回归。

**② 间距刻度**
- 新增 `LocalSpacing`（建议 `xs=4 / sm=8 / md=16 / lg=24 / xl=32` + `screenPadding`），先在 6 个高频页面（SessionHome/Chat/Setting 主页/Board/Novel 项目/History）统一 gutter 为单一值（推荐 16 或 20，二选一全局）。
- `providerRedesignPrimitives`/`CouncilTimelineTab` 的 6–7 种横 padding 收敛到 ≤2 种。

**③ 字号收敛**
- 裸 `fontSize` 映射回 `LocalAmberType`；确需中间值（12.5/14.5/19.5）的进 token 而非散落。
- 修 `StreamingPlainText` 黑色兜底（→ `LocalContentColor.current`）；`StatsPage` 热图标签提到 ≥10sp 或改为非文本标记。

### 5.2 P1（架构纠偏）

**④ 无 VM 页面补 VM（按优先级）**
1. `SettingExperimentalOfficeProPage`（直注 DAO，最严重分层违规）
2. `DeepReadScreen`（6 服务 + 无 VM）
3. `SettingExperimentalWebMountPage`（7 服务 + revision 补丁——`oauthRevision` 说明 store 缺 flow，应让 store 暴露 `StateFlow` 而非 UI 计数）
4. `SettingTodayBoardPage`（4 repo + 11 launch）
5. `MiniAppRunnerPage`/`MiniApp*` 系（11 注入）

模式照抄现有 `BackupVM`/`ChatVM`/`SettingAgentMemoryVM`；页面只留 `koinViewModel()` + 状态收集 + 事件回调。

**⑤ 拆巨石**
- `NovelMarkdownWorkspacePage`（3100 行）按已存在的 composable 边界拆为 `pages/novel/workspace/` 下 ≥6 文件：`Sheet`（Ghostwrite/Polish/Branch）、`Chat`、`Manuscript`、`Catalog`、`Editor`、`Dialogs`。
- `BackupPage` 的 restore 握手（`restoreInFlight`/`restoreObservedLoading` + 3 个 LaunchedEffect 联动）收进 `BackupVM` 用单一 `UiState` 表达。
- `ChatPage`：落地 `ChatPageSplit` 的区域化收集（18 个 flow 下放至各区域），或至少把 L223–281 的文件 IO 移入 VM/Manager。
- `ChatInputSandbox` 内 WebView 提取/缩略图逻辑移到 `feature/webmount` 或 `components/webview` 支撑层。

**⑥ 清理双实现**
- `Markdown` vs `MarkdownNew`：选定主线，另一个删除或明确标注 experimental-only。
- 4 个 `*Split`：要么真机验证后切流删旧路径，要么删实验代码；`PerfFlags` 各 flag 语义统一（当前 `SEARCH_INLINE_IMAGES` 是唯一默认 true 的异类）。

**⑦ 行组件统一**
- 以 `NotionListRow` 或 `ProviderRedesignPrimitives` 为基底收敛 `AmberListRow`（leading 图标位/title/subtitle/trailing 槽/48dp 行高），先覆盖 `setting/` 38 文件与 history/session 列表行。

### 5.3 P2（一致性收尾）

**⑧ 触控目标**：所有 icon-only 可点控件统一 `Box(Modifier.size(48.dp).clip(CircleShape).clickable/pressable)` 包小图标模式（SessionHome 已示范）；`pressable` 补 `semantics` 内容描述参数并逐步替换裸 `clickable`。

**⑨ 防回潮**：新增 lint/Konsist 规则——
- `theme/` 外禁止 `Color(0x…)`（豁免 `SubAgentAvatar` 迁移前白名单、`SimpleHtmlBlock`/`MarkdownNew` 的 HTML 色名解析分支）；
- `pages/` 禁止 `koinInject<*Repository|*DAO>` 与 `import data.db.dao`；
- 单 composable 函数 >150 行报警；
- 页面横 padding 仅允许 `LocalSpacing` 值。

### 5.4 迁移顺序建议

按"先 token 后结构"：色彩/字号/间距（P0）是纯替换、风险低、立即可见一致；VM 拆分与巨石拆解（P1）触碰状态流，需配合 JVM 定点测试（AGENTS.md 要求 Novel 改动先跑定点 JVM 测试）；组件统一与无障碍（P2）可在前两步完成后机械化推进。
