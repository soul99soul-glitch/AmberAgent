# 小说创作功能规格

> Status: Accepted for implementation planning
> Date: 2026-07-12

## Outcome

AmberAgent iOS 新增一级功能「小说创作」。它以聊天作为主要创作体验，同时把用户采纳的正文、项目设定和各剧情分支的演化状态分开管理。

## Entry And Navigation

- Session 首页用「小说创作」替换「核心记忆」入口。
- 入口顺序位于「小应用」与 `WebMount` 之间。
- 小说创作支持多个小说项目；每个项目对应一部小说。
- 项目默认进入「创作」视图，并提供「创作 / 正文 / 设定」三个一级视图；分支管理位于「设定 > 更多」。
- 第一版不是独立 Tab，也不改变普通聊天入口。

## Project And Branch Ownership

- 项目设定由所有剧情分支共享，包括世界观、人物档案、总剧情大纲和写作要求。
- 分支状态独立演化，包括人物经历与当前状态、关系、已发生事件、伏笔和剧情进度。
- 每条剧情分支拥有一个持续的创作 Session，它是该分支唯一能提交正文和状态更新的入口。
- 项目有一条主分支；任一现有分支都可以被设为新的主分支。
- 项目设定修订只对后续生成生效，不追溯改写已有正文或分支状态。
- 分支若需要偏离共享设定，使用显式分支覆盖。

## Chat-First Creation Loop

- 创作 Session 提供「写正文」和「讨论规划」两种模式。
- 写正文支持「续写片段」和「生成整章」两种粒度，默认整章，并记住项目最近选择。
- Agent 的正文输出始终先作为一整块聊天气泡中的正文候选。
- 未收录的正文候选只属于聊天记录，不是已发生剧情，也不更新分支状态。
- 讨论规划保持普通聊天体验；聊天气泡本身不会被收录成新章。已收录正文可由讨论工具 `novel_revise_chapter` 提出段级替换，经审批卡确认后走 `saveManualEdit` 写入，并进入状态待同步。未确认不得改正文。

## Collecting Manuscript

- 正文候选气泡提供「收录正文」动作。
- 收录时按段落多选，默认全选，并提供收录前编辑。
- 用户选择「追加到当前章」或「创建下一章」。
- 正文只以章节为用户可见的管理单位；不引入需要单独管理的场景列表。
- 收录成功后才形成正式创作节点，并触发结构化状态更新。
- 收录正文、手动编辑同步、采用安全润色和恢复章节版本都会形成不可变的分支检查点。
- 创作节点是由正文收录形成的一类分支检查点；无论本次收录的是片段还是整章，它都是撤销和 Fork 的边界。

## Branch State

- 分支状态同时保留追加式事件记录和由事件归纳的当前状态摘要。
- 每次收录正文后自动提交当前分支的状态更新，并显示简短变更摘要。
- 状态更新可查看，不修改项目设定；撤销以最新创作节点为单位，同时回退该节点的正文贡献、事件记录和状态摘要。
- AI 只能提出项目设定修订建议，须经用户确认。
- 生成取消或失败时，已有内容可保留为聊天草稿，但不更新分支状态。
- 正文已保存但状态提取或落盘失败时，保留正文并标记为待同步草稿；它进入完整项目包，但不进入正式正文、Markdown 导出、Fork 或正式生成的注入上下文。
- 手动修改已收录正文后，分支进入状态待同步；允许继续编辑和讨论，但正式正文生成、整章重写和润色前必须先同步。同步成功会新增不可变的修订检查点，不改写旧创作节点。

## Fork

- 任意已完成的创作节点或修订检查点都可以 Fork，包括章节中的一次片段收录。
- 新分支继承该检查点当时的正文版本、事件记录、状态摘要和分支覆盖。
- 分支检查点记录与其内容对应的 Session 游标：正文收录取来源候选位置，润色取润色候选位置，手动同步取同步开始位置；新创作 Session 只继承该游标以前的对话。
- 项目设定继续共享，源分支保持不变，之后两个分支完全隔离。
- 分支支持切换、重命名、删除和设为主分支。
- 唯一分支不可删除；删除主分支前必须先指定新的主分支；删除父分支不会级联删除子分支。
- 第一版不支持自动合并剧情分支。

## Project Material Modules

- 固定核心模块：世界观、人物档案、总剧情大纲、写作要求。
- 自定义资料用于地点、势力、物品、力量体系等自由内容。
- 人物经历、当前状态、分支大纲、事件与伏笔属于分支状态。
- 每个资料条目具有「常驻 / 智能 / 关闭」三态注入模式。
- 当前分支的紧凑状态摘要始终注入；较长历史按相关性智能选择。
- 输入区提供不打断流程的本次注入入口，可查看选择原因和大致占用，并临时加入或排除资料。
- 本次注入清单随生成结果留痕，但临时调整不改变项目默认。

## Whole-Chapter Polish

- 已收录章节提供「整章润色」。
- 固定润色约束禁止新增、删除或重排剧情事件，也禁止改变人物关系、动机、秘密和结局。
- 项目可编辑润色偏好，控制措辞、节奏、描写和对话风格，但不能覆盖固定约束。
- Agent 以完整聊天气泡返回润色候选。
- 系统检查润色前后的剧情事实；检测到疑似语义漂移时禁止按“润色”采用，只能转为手动剧情改写并进入状态待同步。
- 通过检查后，用户点击采用会形成新的章节版本和分支检查点，旧版本可恢复。
- 正常润色不产生状态更新。

## Project Creation And Model

- 新项目支持「快速开始」和「空白项目」。
- 快速开始只收集名称、题材和核心想法；AI 生成设定建议，经确认后才写入项目。
- 空白项目不预生成资料。
- 小说默认提供「创作模型」和「剧情同步模型」两个角色；每个角色都可跟随 Amber 全局聊天模型，也可以单独固定。
- 快速开始、讨论、正文、讨论归档和润色使用创作模型；剧情状态提取、重建与连续性检查使用剧情同步模型。

## Import And Export

- 当前分支正文可按章节导出为 Markdown。
- 完整小说项目可导出为 Amber 项目包，保留设定、全部分支、事件记录、章节版本和创作 Session。
- 项目包可以完整导入恢复。
- 第一版不做 iCloud、WebDAV、多人协作或云同步。

## Collaboration Modes

- 项目级 `collaborationMode` 区分**共创模式**与**代笔模式**；顶栏标题打开项目控制面板可切换。
- 共创：正文候选须用户收录才进正史（默认路径）。
- 代笔：切入前须策划包就绪（总纲、人物、写作要求、分支已同步、无阻塞 pending/active run）；写整章前须确认**本章合同**。面板可启动单章代笔：写整章 → 结构化合同验收（剧情同步模型）→ `systemAutoCollect` → 剧情同步；失败/暂停则停住。详见 `NOVEL_COCREATION_GHOSTWRITE_PLAN.md` Phase 2。
- 本章合同为分支级可选（共创）/ 强制（代笔写整章）工件；确认后冻结 content digest；有确认合同时整章散文注入与候选绑定该 digest；digest 不匹配不可收录。
- 跨章防复读（Phase 3a）：状态快照携带有界「近期已写要点」；整章注入防复读；验收可标明显复读并暂停自动收录（软门，非独立审稿模型）。

## Acceptance Criteria

- 普通聊天的会话、上下文和分支行为不受小说创作影响。
- 未收录正文候选永远不会进入正文、事件记录或当前状态摘要（代笔自动收录启用后仍须走同一领域收录事务）。
- 收录正文要么完整提交正文与状态更新，要么保留可恢复的待同步状态，不丢正文。
- 最新创作节点撤销时，正文贡献和分支状态必须一起回退；不存在只撤状态的合法结果。
- 项目设定和分支状态不存在旧快照互相覆盖。
- Fork 后源分支不变，子分支从准确的不可变检查点继承并独立落盘。
- 取消、错误、后台中断、重试和重复回调不会重复提交创作节点或状态更新。
- 手动编辑后的过期状态不会被用于下一次正式正文生成。
- 整章润色保留旧版本，安全采用不改变事件记录或分支摘要，语义漂移不能绕过状态同步。
- 每次生成能够追溯实际注入资料和项目模型。
- 项目、分支、章节、状态、版本和创作 Session 在重启后完整恢复。

## Explicitly Out Of Scope

- 自动分支合并。
- 多个 Session 并发写入同一剧情分支。
- 场景级正文管理。
- 在「创作模型 / 剧情同步模型」之外，继续按正文、讨论、润色等任务拆分更多项目模型。
- 云同步和多人协作。
- 任意字符范围的正文收录；第一版使用段落多选和收录前编辑。
- 代笔**无界**连写、离屏完整世界模拟与完整生产看板。有界多章代笔（最多 10 章、首章用户确认合同、后续自动拟合同）见 Phase 4。跨章防复读薄回执已启用（Phase 3a）。共创仍必须人手收录；代笔自动收录已启用。
