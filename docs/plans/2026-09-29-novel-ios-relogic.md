# 小说创作按 iOS 页面逻辑重做(2026-09-29)

用户裁定:小说创作页面与逻辑混乱,按 iOS **页面层级与呈现逻辑**重做(控件样式用鸿蒙既有设计族,不逐像素复刻)。

## iOS 基准(amberagent-ios NovelCreation,约 7.9k 行 UI)

- 路由三层:项目列表 → 三 tab 工作区(创作/正文/设定) → 章节阅读器(push)
- 列表页:右上导入+设置,底部悬浮新建胶囊;创建 sheet 分「空白项目/快速开始」,
  快速开始含题材+核心想法(AI 只生成建议,确认才写入)
- 工作区顶栏:居中 principal 钮(项目名+副标题:模式·分支·模型)开「项目控制」sheet
- 创作 tab:单聊天流;composer meta 行(模型 chip + 创作方式 menu(讨论/写一段/写整章/
  归档当前讨论));无顶部工具行
- 正文 tab:目录头(目录+批量润色+共 N 章)→ push 阅读器(principal 第N章·字数+标题,
  ⋯菜单=版本历史/编辑/整章润色/整章重生成/废弃/删除,底部上一章/下一章,Markdown 正文)
- 收录:气泡「收录」→ 四段式 sheet(选段落→收录前编辑→位置 替换/并入/新开)
- 收录整章后自动 offer 讨论归档
- 设定 tab:segmented 角色/世界观/剧情/更多;剧情含连续性审计+分支走向+时间线

## 鸿蒙现状痛点(用户视角)

- 顶栏:项目名左置+「主线▾」+「导出」散装;无项目控制中枢
- 创作 tab:顶部「批量代笔›+归档讨论」工具行突兀;模式 chips(讨论/续写/整章)常驻;
  无模型可见性
- 正文 tab:阅读器内嵌 tab 内(←目录/编辑/删除裸文本行,正文纯 Text 无 Markdown,
  无上下章导航),⋯菜单与阅读器操作割裂
- 收录对话框只有位置列表(新开/并入/替换),无段落选择与收录前编辑
- 设定 tab:工作区设定/资料库两 chips,模型职责/计划偏好/伏笔/决定/审计散置
- 列表页:新建藏顶栏文字,无快速开始入口(域层 quick_start 已备)

## 批次

- A 列表页:右上导入 icon;底部悬浮新建胶囊;创建 sheet(空白/快速开始 Seg+题材+
  核心想法);空态双按钮;恢复删除改 footer 链接;快速开始创建后带种子直进工作区自动发
- B 工作区骨架:顶栏 principal 钮(项目名+模式·分支·模型)开项目控制 sheet(共创/代笔
  +代笔卡+写作模型+本章计划+写作偏好+分支管理+导出);tab chips 换 Seg;创作工具行撤
  (代笔入项目控制,归档讨论入创作方式 menu);composer meta 行(模型 chip 开项目控制)
- C 章节阅读器 push 页(NovelChapterReaderPage):MarkdownText 正文、⋯菜单(版本历史/
  编辑/整章润色/整章重生成/废弃/删除,含阻塞原因)、上一章/下一章胶囊;目录行去 ⋯
- D 收录 sheet 四段式(段落勾选+收录前编辑+位置 Seg);整章收录后讨论归档 offer
- E 设定 tab 重组:Seg 角色/世界观/剧情/更多;剧情=总纲+伏笔+已确认决定+连续性审计
  (从正文 tab 挪);更多=模型职责+计划偏好(NovelSettingsPane 整件)+其他资料

每批一 commit,lint 0 error + build + 真机截图验证。
