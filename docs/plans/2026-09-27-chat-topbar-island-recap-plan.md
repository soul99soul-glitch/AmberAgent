# 聊天页顶栏：岛 + 回顾 + 产物架（Android）

日期：2026-09-27
参考：iOS 已落地同类交互（`ios/docs/product/chat-topbar-dock-plan.md`，Phase 5 回顾）。本文只记录 Android 的设计与证据，不把 iOS 结果当作 Android 已验证行为。

## 顶栏新布局

```
[返回]  [ 岛：状态 / 短标题 ]  [产物架]
        [ 模型名 ⌄ ]
```

1. **岛**（原会话标题行）：独立点击区域。
   - 生成中：显示当前状态（`processingStatus`，缺省为「正在生成」），点按跳到时间线最新位置，长按停止生成。
   - 空闲：显示短标题。当前分支用户消息 ≥ 3 条时点按展开「回顾」；不足时岛轻鼓一下，提示「再聊几轮就能回顾」。
   - 空对话：不响应。
2. **模型名行**：独立点击区域（≥ 44dp 高），照旧打开 `TopModelMenu`。
3. **右上角**：上下文占用环移除，换成产物架按钮；无消息时隐藏。
4. **上下文占用**：挪进 `TopModelMenu` 顶部，作为一行「上下文 used / total」+ 本轮 token / 缓存命中 / 速度。

## 回顾

面板顶部是对话标题（点按可改名），然后是：概述 → 关键节点（3–8 条，可点跳转并高亮）→ 接下来（点按填入输入框，有草稿时换行追加，不自动发送）。有新内容或切了分支时顶部显示「有新内容 · 刷新」。

- **生成时机**：每轮正常结束后后台生成（`ChatService` 成功副作用，与标题、推荐问题并列），门槛为当前分支用户消息 ≥ 3。从未生成过的对话，打开面板时当场生成；上次后台失败也会在打开时重试。
- **模型**：复用 `titleModelId`，`ReasoningLevel.OFF`。
- **提示词**：当前分支消息编号为 `m1…mN`，每条截断到固定字符数，工具只保留名称与简短输入；总长设上限，超出时保留开头与最近的消息。已有回顾且其终点仍在当前分支时做增量：旧回顾 + 之后的新消息。
- **解析**：容错提取 JSON（允许代码块包裹、前后多余文字），节点数量超出时截断、不足时照收，引用不在编号表内的节点丢弃。
- **跳转**：节点保存 `nodeId + messageId`。只有该节点当前选中的消息仍是同一条时才可点；跳转前 `ensureTimelineLoaded()`，再 `lazyIndexForMessage` → `animateScrollToItem`，并短暂高亮。
- **存储**：`filesDir/conversation_recaps/<conversationId>.json`，不在 `SYNC_FILE_ROOTS`、`backup_rules`、`data_extraction_rules` 内，所以不进备份，恢复也不会改写它；会话最终清理时删除。写回只按请求时的会话 id 落盘，写前写后各确认一次会话仍存在。因为不写数据库，不走恢复 epoch 门控。
- **过时判断**：记录覆盖的分支消息 id 列表 `branchMessageIds` 和最后一条消息的内容签名 `tailSignature`。id 列表或签名与当前分支不同即过时（签名用来发现续跑时在同一条消息里追加的内容）。

## 产物架（MVP）

当前分支中的图片、文档附件、小应用、网页引用（`UrlCitation`），按出现顺序倒序列出；点按项收起面板并跳到对应消息。版本叠放与 diff、固定到产物架、跨对话提醒不在本期。

## 分期

- **Phase A**（本期）：顶栏拆分 + 岛 + 回顾 + 占用挪入模型菜单 + 产物架 MVP。
- **Phase B**：产物版本叠放与 diff、固定消息到产物架、「从这里继续」。
- **Phase C**：应用级跨对话动态中心（等待确认 / 失败 / 完成），产物架按钮变提醒入口。

## 验证

- JVM：回顾提示词构建、解析容错、过时判断、产物收集、存储读写与删除。
- 编译：`:app:compileDebugKotlin`，再按风险 `assembleDebug`。
- 设备：模拟器或真机点岛、看回顾、跳转、模型菜单占用行、产物架。

## Phase A 实现记录（2026-09-27）

- 回顾：`core/recap/`（`ConversationRecap.kt` 纯逻辑、`ConversationRecapStore`、`ConversationRecapGenerator`），`ChatService` 成功副作用触发生成，`ConversationRepository.cleanupDeletedConversation` 删除回顾文件。
- 界面：`ChatTopBarPanels.kt`（岛、产物架按钮、无尖角面板、回顾与产物架内容、改名对话框、跳转高亮），`ChatShelfItems.kt`（产物收集）。`ContextRing` 不再挂在顶栏，内容抽成 `ContextUsageSummary`，放进 `TopModelMenu` 的 `header`。
- 顶栏高度 56 → 60dp；模型行点击区 26dp 高，未达到计划里的 44dp（要达到需把顶栏加高到约 76dp）。
- 页面窗口只含最新几页，UI 侧用 `freshnessForWindow`（后缀匹配）判断过时；生成侧用完整会话精确比对。
- 验证：新增 JVM 测试 9 项全过；chat / service / repository / recap 相关测试 95 项全过；`KoinGraphVerifyTest` 仍只报既有的 `JevDecisionCoordinator` 缺失。模拟器（API 35）上确认：顶栏布局、回顾失败态（未配模型）、手工写入回顾后的完整面板、点节点加载旧分页并跳到第 513 条、产物架空状态、模型菜单占用行。
- 未验证：真实模型生成的回顾质量；生成中岛的状态文字与长按停止；不满 3 条时的轻鼓提示；有产物时的产物架列表；真机手感。

## Review 修复（2026-09-27）

两个 subagent 分别做了逻辑与界面 review，修复如下：
- 历史分页：`loadOlderTimelineBatch` 在查询被取消或出错时复位 `prefetchingOlder`，避免往上滚动不再加载历史。跳转效果改为只以目标为 key，先整段加载，再用 `snapshotFlow` 等目标进入 timeline plan；加载后再核对一次选中的消息 id。
- 回顾：
  - 生成器在完整会话不满门槛时写入 `ineligible` 终态，面板不再一直转圈。
  - 没有模型时写入 `NO_MODEL`，面板直接说明原因。
  - 读取完整会话失败时写入失败状态，不会让应用崩溃。
  - 只在正常完成且没有待执行工具时后台生成，并且先用分页窗口判断门槛，不够的短对话不做全量加载。
  - 打开面板时统一交给生成器，在完整会话上做精确比对。
  - 强制刷新会排在正在进行的请求之后执行，不会被丢弃。
- 产物架：不再把整段时间线加载进页面，而是在分页窗口之外读取完整会话；消息数或最新一条消息变化时才重算，流式输出期间 400ms 内的连续变化合并成一次。
- 可回顾判断：只在消息数变化时统计用户消息，统计放在 `Dispatchers.Default` 执行，不再每个流式分片都遍历一遍。
- 界面：
  - 面板底部让出底栏和键盘的位置，内容超出时加底部渐隐。
  - 圆角改用主题的 `shapes.extraLarge`，标题改用 `screenTitle`。
  - 失败节点用错误色，产出节点用空心圆，节点文字统一用正文色；圆点对齐首行，放大字号时也对齐。
  - 分段间距统一。
  - 高亮向外扩 8/6dp，长消息拆成的各片也会高亮；新高亮不会被上一次的淡出截断。
  - 长消息跳转时对齐到消息开头。
  - 岛加细描边，禁用时变淡；产物架按钮激活圆改为 32dp，图标用 ink 色。
  - 顶栏改为最小 62dp 高，模型行最小 28dp 高。
  - 内联 data URL 图片的标签回落为类型名。
- 未处理：
  - 每轮额外一次标题模型调用，没有开关（产品决策）；
  - `ContextRing` 组件已无调用方；
  - ja/ko/ru 没有翻译；
  - 长按停止没有触觉反馈；
  - 横屏时面板可用高度很小，只能滚动查看。
