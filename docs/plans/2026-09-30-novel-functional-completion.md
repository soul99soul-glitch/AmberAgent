完成标准：作者能够创建或导入项目，维护设定并确认计划，讨论和写作，正确收录、改稿和润色，正文派生剧情与上下文保持一致；作业可暂停、恢复和安全重试，备份可恢复。高风险写入检查来源或 CAS，失败真实可见。必要功能都有生产入口、持久化与聚焦验证；UI 更改需要构建、签名和截图检查。

## 去留判断

判断“必要”的依据是正式稿正确性、输入保存、长篇上下文、已经提供的功能是否真实闭环，以及项目数据保全。当前活跃却可选的 iOS 功能不称为废弃。

必要补齐：A02/A06 损坏项目可见与恢复，A07 完整备份，A09/A10 公开工作区互通和领域恢复，A15 历史正文预览，A16 起步提案确认；B04 草稿，B08 工具隔离，B13–B16 收录正文/目标/取消/来源版本，B19 有效归档，B22/B23 停止保存和失败输入；C06 资料采用目标，C08/C09 自动约束和预算，C12–C15 正文剧情一致性、真实重建、门禁和完整审计；D02 计划作者确认，D05 未来方向正确消费，D09 单章润色安全采用，D10 重生成来源；E01 职责模型继承一致，E04 结构化错误可见；F05 UI 和设备验收。

保留鸿蒙现有等效方案：CAS 工作区提案已经可以改稿和删章，不复制 iOS 的二十种专用工具；分支快照保证资料隔离，不复制资料 revision/inheritance 图；润色失败停止后定点重试是有效策略，不强行改成失败继续；批量润色、代笔和后台保持 durable job，不复制 iOS VM 批次状态机；完整富消息继续保存，正式稿仅提取 text；软删除恢复、TXT/EPUB 和冷启动调度是鸿蒙现有能力。

可后置的活跃 iOS 功能：历史 checkpoint Fork、多步 undo、分支设主线，人物别名智能识别与经历聚合、复杂资料分类与规则预览、环形注入面板和完整历史凭据、已收录克隆、独立搜索研究工具、自动连续性修复、定向改稿流水线、任意选章、多层全局模型设置、系统分享。章内查找替换可作为编辑便利功能，但不阻塞本次主闭环。没有用户使用率证据，不能称这些能力“基本废弃”。

不移植的明确旧链：

- iOS `NovelProjectLifecycle.swift:159` 和 `NovelFactTransactionLifecycle.swift:242` 明确新写入已退休 model plot draft；普通改稿使用确定性正文指针，full-sync 保留异常救援。鸿蒙采用前者，不建立常规多段模型同步链。
- iOS `8dec17d` 已将旧 accept plan → standalone candidate continuity audit → collect 改为联合裁决收录；旧自动削合同/改单项 must 的执行函数被删除。鸿蒙保持作者确认与冻结摘要，不新增残留开关 `pauseGhostwriteOnBlockingContinuity`。
- `NovelMaterialsView` 旧页面和旧独立 `NovelInjectionPreviewSheet` 没有生产实例化，能力已进入 Compendium 和当前项目控制。共享资料编辑器仍活跃，不能把整个源文件当死代码。
- iOS monofile、root sharded、legacy-package 是自己的旧存储兼容层，不在鸿蒙新增；at-rest completed runs/receipt/factAttempts 本身会裁剪，不复制永久全量日志仓库。
- 鸿蒙旧 `NovelBatchPolishSheet` 无生产入口，不复活；生产入口是 `NovelPolishCreateSheet` 与持久作业卡。
- iOS 远端 Responses 游标、音频保活、Live Activity 和 BG API 按 provider/平台而存在，不移植到鸿蒙；验证鸿蒙自己已有的后台能力。

## P4 细化后的接线与验证

1. 快速开始以结构化分项返回，绑定本次实际持久助手消息与分支；只创建 pending 设定提案，不自动成为正式资料。稳定提案身份保证重放不重建已决项；UI 用概览及提案卡展示，保留 canonical 原消息。
2. 代笔启动先展示作者完整 Markdown 与目标章数。预览的计划与 CAS 来自一致快照；确认直接校验该 CAS，计划、正文或分支变化后必须重新预览。不编造必须发生/不可发生约束。
3. Reader 和 Workspace 两个单章润色入口统一到 durable 单章目标；使用真实 ordinal（含公开导入的独立章号），复用现有审核、恢复和原子收录。没有第二个润色作业状态机。
4. 全文审计按生产发送预算分块读取所有有效正文，包括超长章节开头和长书后段；保留范围、失败块和覆盖比例。证据绑定章节 ID、正文 digest 和原文 quote；无效证据不得算已验证问题，UI 可以跳回当前章并说明旧稿证据。
5. 最近完成代笔报告投影既有 durable 状态和收录凭据；当前 active-job 查询继续只负责活动锁，历史报告不锁住新写作。
6. 聚焦验证覆盖预览后计划/正文/分支变更、快速开始重放与坏 JSON、真实单章目标与恢复、120k 后段及 18k 前段覆盖、失败块部分报告、无效证据和历史报告不锁 workspace。每条实际生产调用链均独立 review。

## P5 精确范围

1. Reader 历史列表先打开完整标题、时间、版本类型和 Markdown 正文预览，再由作者确认恢复；恢复复用原有领域事务，不引入 diff 或新历史库。恢复期间各关闭入口遵守现有 busy 状态。
2. Reader 页面及浮层纳入既有 themeEpoch 整页重挂载，补历史、菜单底部安全区的已知零值场景。
3. Workspace 章节与资料编辑器保存前提交输入法预编辑，按既有 Reader 的 controller/stopEditing 模式实现。保存入口、关闭和编辑控件遵守 busy，阻止重复创建和旧保存误关新编辑器；失败保留原稿及可见错误。
4. 章节列表与收录目标显示真实 ordinal，避免公开导入和删章后与任务范围不一致。资料类别单行改为已有的横向 Scroll 模式，解决五个类别在小屏卡片可用宽度中溢出的确定问题。
5. 独立 review 核对全文预览、恢复调用链、IME 提交和取消、主题消费、44vp 点击区和局部布局。当前无符合用户约束的设备，截图和实际键盘/深浅色门继续 pending，不用源码推断代替实测。
6. 实际复现公开导入 ordinal 7 后手工新增得到 fallback 2，公开导出/重导入把新章排序到第 7 章之前。手工新增与收录新章统一为现存章节最大 ordinal + 1，显式持久化并同步默认标题；保留旧项目 fallback，遵守原有 999 章上限。不增加永久编号占用记录；删除最高章后可以重新使用已移除的编号，新章节仍有独立身份。
