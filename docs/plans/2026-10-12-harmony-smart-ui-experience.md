## 决定与完成标准

沿用已有 `amber-ui v=1` 的逐行声明、卡片来源身份与 KV 草稿 owner，不另建 `task-ui` 协议或发送框架。旧六类节点继续可读。扩展有界原生组件描述，并使用固定目录和设计 token；用户当前值继续由宿主持有，展示状态与任务输入分别处理。

1. **组件与状态**：对照参考会话中的 80 种原生组件，落实布局、文字、状态、输入、数据、媒体、任务内容及操作展开。新控件必须有真实值校验、恢复及原生渲染，不把样式别名计为控件。每张卡片继续受节点、深度和字节预算约束。
2. **任务继续**：按钮填入的草稿带可读的当前选择与输入快照，保留用户原文字及附件；用户仍通过现有发送入口发送。明确文字“按这个继续”只读取当前会话、当前选中分支中最近实际修改或通过按钮确认的有效卡片；普通问答不附加字段。发送前异步检查完成后复核来源，来源失效保留输入并提示确认。
3. **能力说明**：模型只获知实际实现的组件与字段。充分信息及授权时直接完成任务；卡片用于有必要的选择和输入，不能替代事实调查或新增审批等待。
4. **验证**：协议、控件状态、快照、分支、持久化及旧内容回归；受影响 ArkTS lint、完整构建、签名；模拟器默认聊天路径截图及代表性控件操作。真实 provider 与真机单独记录，未取得的证据明确保留。

## 已完成的实现与复核

- `smart_ui/components.ts` 统一定义 80 个组件的目录、值类型及显示语义；`protocol.ts`、`interaction.ts`、`persistence.ts`、会话 artifact 深拷贝均接入组件信息。复用旧协议的节点、状态、来源与内容预算。
- `NativeSmartUiComponent`、`NativeSmartUiInputs`、`NativeSmartUiData` 分别负责展示/布局、输入、数据；递归仍由 `NativeSmartUiNode` 的 builder 管理，没有新增 WebView 或脚本执行权限。
- `continuation.ts` 提供明确文字继续、任务字段快照和当前消息中的卡片查找；Page 作为当前值 owner 负责草稿与发送预检。按钮携带节点身份，由 Page 点击时读取 action 和值，避免局部控件 props 尚未刷新造成草稿文本与快照矛盾。
- 原生能力提示接入真实目录和可解析的任务示例；Debug 回放在默认聊天渲染路径展示八类组件和任务卡，默认不调用 provider 或写会话 RDB。

独立阶段审查与一次有限可维护性检查已完成。确认并修复了选项 ID 与解码范围不一致、旧按钮引用展示状态、非法编辑未到 Page、列表 items 不显示、非步格上界与小步长、filled 子内容对比度、图片 URL 更新、流式落盘来源误拒等问题。模拟器快速输入还取得了局部 props 落后导致草稿文本与快照不一致的复现，改为页面当前值统一生成。

深色截图发现输入占位文字和滑轨对比不足，显式接入主题颜色。模拟器进一步取得 `THREAD_BLOCK_6S` 故障栈：`Card.onInitialValuesChanged → reconcile` 与原生文本回灌形成更新循环。Card 在相同标量时停止重复写入，并仅在值、非法字段和诊断语义变化时更新数组；Page 的相同值通知也不再改变交互次序。复现测试覆盖 100 次回灌、恢复 watcher、不同输入/清空及定义变化，独立复核通过。

快速原生输入进一步复现字符丢失：组件只等待父级 `@Prop` 更新，下一次输入仍读到旧值。输入组件现在先替换自身局部 prop 副本，再同步通知 Card/Page，不修改传入数组，也没有增加计时器或焦点状态。最终 HAP 在键盘打开且文本框仍聚焦时，完整输入 `offline`，并验证重置后继续按钮禁用。
