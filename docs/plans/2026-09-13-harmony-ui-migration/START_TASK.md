## 目标与范围

把范围内所有鸿蒙现有页面、深层子页、tab、sheet/dialog 和关键状态逐批改为 Android 基线的设计语言，并保持真实功能可用。重点包括布局、排版、颜色、图标、圆角、阴影、滚动、转场、反馈和关键交互。

沿用鸿蒙现有业务、数据、导航和平台服务。视觉重构若涉及回调、状态、保存或权限接线，需要沿真实路径验证。缺少整项功能时登记差异和依赖，先继续可做的页面；不得为了凑齐截图加入假功能、硬编码成功状态或把实际能力替换成演示内容。

用户授权你在已核实的目标工程中持续完成本次 UI 实现、必要修复、构建和可用模拟器上的验证。遵守本机已有权限和仓库约定；不据此推送、发布、清除用户数据、修改无关仓库或覆盖既有 WIP。真机涉及替换用户现有安装时，先核对已有授权、签名和保留数据能力。

## 第三阶段：先样板，后批量

依赖顺序优先于页面数量：先把实际需要的公共颜色、字号、间距、圆角、卡组和导航外观在鸿蒙现有结构中校准，避免新建庞大设计系统。

首批样板选择：

- 首页：搜索、日期、继续/功能卡、会话列表、新对话入口及真实导航。
- 设置首页：分组、行高、图标、辅助文字、顶栏与深浅主题。
- 提供商详情/编辑：表单、tab、sheet、原始输入、保存/取消和真实配置消费。
- 聊天主路径：空态、消息、生成/停止、思考和工具展开、审批、键盘与底部状态栏。

样板达到参考要求后，按页面族继续：设置各分支 → 会话/搜索/收藏 → 看板/深读/资料统计 → Novel/扩展编辑/小应用/议会 → 平台能力/备份/远程 WebView 壳和辅助页 → 全局回查。根据鸿蒙真实依赖调整并记录，已完成样板不重复计数。

普通批次通常 3–6 个相近页面，复杂工作区单独成批。不要大面积改完几十页才第一次运行，也不要默认每批结束都要求用户再说“继续”。首批可以给用户展示方向；已有充分参考且无实质决策缺口时继续推进。

Android 的视觉语义在鸿蒙上复刻；字体度量、安全区、键盘、系统返回、权限/文件/分享等系统 UI 按鸿蒙实际能力适配。平台例外必须写清原因与保留行为。不要以“平台差异”为理由任意简化应用自有阴影、动画、密度和布局。

## 执行循环与恢复规则

基线与环境齐备后，请把这个有明确终点的迁移设置为可用的长期目标（例如 Codex 的 `/goal` 功能），按下面的文件推进；如果当前 AI 不支持持续目标，也照此执行和保存检查点，不声称已经启动后台任务。不自行设置定时器、无限重试脚本或修改全局模型/额度配置。

每轮执行：读进度和实际 diff → 选择依赖就绪的一批 → 读取对应参考 → 实现 → 最小充分构建/测试 → 运行并截图对照 → 修正 → 验证关键动作 → 写入证据和下一步 → 继续下一批。

- `TASKS.md` 是唯一进度清单。每行记录 ID、页面/关键状态、Android 参考、鸿蒙入口与文件、依赖、状态、证据链接和阻塞原因。
- 状态为 `pending / in_progress / implemented / verified / blocked`。代码完成不等于视觉已验证。平台例外另列依据，不能偷偷从分母中删除。
- `PROGRESS.md` 每批追加简短记录：修改范围、已通过验证、未验证项、当前阻塞、下一批、涉及文件。能从磁盘记录和 Git diff 恢复，不依赖旧聊天仍在上下文。
- `DECISIONS.md` 只保存影响后续的决定，例如主题映射、图标资产、平台例外和用户修正，避免重复判断。
- 中断恢复时先核对当前 diff、已有产物和任务状态，不能把旧的 `in_progress` 当成完全没做；只补尚未完成的工作。
- 有其它独立待办就绕过具体阻塞继续。全部剩余任务都受阻时给出具体缺失条件和待恢复入口，不编造完成，也不反复执行同样失败的动作。

## 验证要求

每页看布局和实际行为。Android 与鸿蒙使用尽量一致的逻辑视口、测试内容、语言、字号和主题，把两张图放在同一对照中审视并修正明显差异。文字不截断、层级和留白正确、图标素材一致、浮层和固定栏位置正确、点击区域可靠。动效和滚动用实际操作或短录像验证。

每页至少有主状态证据；只补实际存在且影响布局/行为的状态。共享组件覆盖深浅主题与窄屏/大字号后，针对聊天、表单、编辑器等高风险页面补测。不写穷举组合、源码字符串断言、私有实现测试或只为了覆盖率的测试。

重点保护这些真实行为：列表分页和滚动、聊天流式跟随、编辑中间态、即时保存与显式保存/取消、弹层展开/关闭、返回栈、主题切换、权限含义，以及持久化后重新进入页面的状态。新增测试只覆盖本次行为变化或已复现问题；纯样式改动以适当编译和实屏检查为主。

区分证据：源码推断、编译/测试、模拟器、真机、Provider 网络/真实账号不可互相替代。没有运行到鸿蒙真实页面就不能标记视觉通过；本地测试数据和静态远程网页样例不能证明真实服务可用。

已通过的验证不无故重跑全量。公共组件或导航后续改动时，对直接受影响的已完成页面做必要回查。

可委派相互独立的页面族；共用 token/组件、导航和同一设备各有唯一负责人，避免重叠写入与设备竞争。按本机已有子代理配置和仓库约定路由，不改变主代理配置。主代理负责集成、范围和最终证据。
