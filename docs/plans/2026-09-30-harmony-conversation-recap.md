# 鸿蒙对话回顾实施计划

目标：对话页顶部上层打开结构化回顾，下层切换模型与服务商；回顾具备概览、关键节点、下一步、原消息定位、更新/重试与独立持久化。沿用 iOS 已验证的产品口径，不扩展设置项或通用状态框架。

## Phase 1：数据与生成闭环

- 对齐 iOS：至少 3 条用户消息；概览约 120 字；决策/里程碑/失败/产物节点最多 8 个；下一步最多 3 个。
- 使用独立 KV 缓存，不改会话消息或备份格式；生成使用标题任务模型，自动选择时回退当前对话模型，关闭推理及工具。
- 成功完成对话后生成/更新；用户首次展开或刷新时可立即生成。同会话请求合并，切页后结果仍归属原会话。
- 保留当前分支的稳定消息引用；追加内容、编辑或切换分支后标记需更新；删除和恢复清理缓存并隔离在途结果。
- 必要测试：解析与真实消息引用、增量/分支、请求归属及删除/恢复失效。
- 完成后 subagent 只读 review，修复有证据的闭环缺口。

## Phase 2：顶部与回顾面板

- 上层标题做紧凑圆角动态区域，空闲显示会话标题，整理中显示状态；点击打开回顾。下层模型行独立点击进入现有服务商/模型菜单。
- 回顾面板复用主题、遮罩、动画和可滚动容器；概览、分类节点、下一步、加载/失败/更新状态清晰可操作。
- 节点定位复用已有节点定位；目标不在当前窗口时，从展开回顾时已读取的完整会话构建目标窗口。下一步填入草稿而不自动发送。返回、点击遮罩、关闭按钮均可退出；离页退订。
- 保持修改局部：纯数据逻辑与面板独立文件，ChatPage 仅做接线。
- 完成后 subagent 检查调用链与 UI 热区、对齐、间距、溢出及主题。

## Phase 3：产品验证与收尾

- 只运行新增回顾测试与改动文件 lint、构建、签名。
- 模拟器验证：上下两层入口、不足消息提示、正常生成与缓存、节点定位/草稿、刷新/失败、关闭/返回；浅深色检查布局。
- 用本地确定性 provider 验证请求与界面链路，不把它等同于真实付费服务验收。
- 最后 subagent review 实际改动与截图证据；修复确认问题，记录通过与未验证的边界。
