# Amber Android UI 全面审查报告

日期：2026-09-12 · 范围：`feature/ui/pages/` 全部 22 个子目录 + `feature/ui/components/` 全部 + `feature/live/bubble/` + `agent/RouteActivity.kt`
方法：17 个并行批次静态代码审查，约 120 个文件 / 约 90,000 行 UI 代码；标尺 = `AmberTokens` / `AmberType`（7 档字阶）/ `AmberPrimitives`（pressable、AmberCard、Hairline、BtnInk/BtnAccent、LiveDot、SectionLabel）。
分级：**P0** 错误级（必然出错）· **P1** 功能错误或明显不一致 · **P2** 打磨级。所有问题均带 `文件:行号` 证据；标注"(待确认)"的需实测复核。本报告为静态审查，未做模拟器截图验证。

## 1. 总体结论

设计系统底座（`ds/AmberPrimitives`）本身干净克制、质量高，但**全 App 只有约三分之一的界面真正接入了它**。其余界面停留在三套旧体系上，导致同一 App 内同屏可见的字号、圆角、边距、按压反馈、颜色语义系统性漂移。另有一批与美观无关的**行为级 bug**（导出产物损坏、逻辑谓词失效、开关不持久化等）和**约 1,500 行零引用死代码**。

## 2. 系统性横切问题（最高杠杆，先于逐文件修复）

### S1 · 五套颜色体系并存（最大单一问题）
`LocalAmberTokens`（设计系统）· `workspaceColors()`（**75 个文件、268 处调用**的16 色裸 hex 第二调色板）· `LocalChatTheme`（聊天页主题，且有 5 个通用组件反向依赖它：ChainOfThought:174、SubAgentAvatar:19、Input:35、Select:33、WorkspaceSearchField:41）· `MaterialTheme.colorScheme`（M3 默认）· `CustomColors.extendColors`（12 处）。典型恶果：
- ProviderConnectionTester.kt:296-312 —— `signal` 已别名 `accent`（AmberTokens.kt:117-118），**连接测试"成功"与"失败"恒为同一颜色**，且错误语义复用品牌 accent。
- 同一组件内多源混用：ChatMessageTools.kt:386-414 胶囊三源取色；ChatMessageMessagePartsBlock.kt:266-268 同一行内用户气泡取 ChatTheme、助手气泡取 workspaceColors；SettingAgentMemoryPage.kt:717-725 设置页里出现聊天主题"颜色飞地"。
- DeepReadScreen.kt:1985-2006 `magazinePalette()` 全量裸 hex（浅色 accent=红色 0xFFEF4444），不随用户 accent，与品牌 terracotta 冲突。
- **方案**：workspaceColors 16 槽语义映射进 AmberTokens（canvas→bg、paper→surface、row→surface2、ink→ink、muted→ink3、hairline→line），blue/green/amber/red 升格为与 accent 并列的固定语义色；按"setting 23 文件 → chat+message 16 文件 → 散点"三批替换；约定新组件只准 LocalAmberTokens。

### S2 · 字阶失控（7 档之外散落 30+ 种 raw 字号）
字阶定义 19/16/15/13/12/11/10.5sp，实际采集到 5.5 / 8 / 9 / 9.5 / 10 / 10.5覆写 / 11覆写 / 11.5 / 12.5 / 13.5 / 14 / 14.5 / 15 / 16覆写 / 17 / 18 / 20 / 22 / 23 / 24 / 26 / 29sp，另加 M3 typography 全套与 Markdown 文档阶 24-14sp。重灾区：SessionHomePage 15 处（最小 9.5sp 状态 chip）；SettingSearchListCards 整文件无一档字阶；ProviderTabPage 表头 9.5sp 近不可读；WorkspaceTopBar 22sp 造成全 App 二级页标题漂移；ModelList.kt:739 `letterSpacing = 0.15.sp × 字符串长度`（字距随字数变化，疑似想写 0.15em 的 bug）。
- **方案**：立一条规则——`fontSize=` 只允许出现在 theme 层；页面需要新档位先补进 AmberType。Markdown HeaderStyle 收编为"文档字阶"且 H1 不超 screenTitle。

### S3 · 触控目标系统性低于 48dp（20+ 处 <40dp，最小 10dp）
高频重灾：ContextRing 触发器 ≈20dp（ContextRing.kt:115-121）、沙盒 pill 取消键 18dp/翻步箭头 16dp（ChatInputSandbox.kt:714-716,760）、排队消息取消 26dp（ChatListIndicators.kt:477）、消息操作按钮 34dp（ChatMessageActions.kt:175）、分支切换 32dp（ChatMessageBranch.kt:48）、MessageJumper 36dp×4（ChatListSubViews.kt:276-344）、代码块复制/下载 24dp（HighlightCodeBlock.kt:420-427）、ToolResultPreview 翻页箭头 9dp（:291,304）、设置域 SourceChip/ChoiceChip/TemplateChip ≈30dp、ExperimentActionButton 36dp（SettingExperimentalPage.kt:315）、MiniAppGridCard 菜单 24dp（:109）、PromptPage chip 删除钮 16dp（:1064）、TagList 删除 X 16dp、附件移除徽章 18dp（CouncilRoomComposer.kt:641）、SlidesFont 下载 32dp/菜单 36dp、TabPage 行内添加 28dp（:623）、WebMount 导航键仅一个字符宽（SettingExperimentalWebMountPage.kt:1001）。附件 chip 还出现"32dp 设计 vs 48dp 热区盒"互相打架（ChatInputAttachments.kt:307-323）。
- **方案**：全局 sweep，凡可点一律 `heightIn(min=48.dp)` 或改用 ds 原语；附件/徽章类小目标用 `minimumInteractiveComponentSize` 扩热区。

### S4 · 圆角无体系
体系值 14dp（卡）/15dp（按钮），实际出现 2/3/4/5/6/7/8/10/11/12/16/18/20/22/26/28/32dp、`RoundedCornerShape(50)`（百分比与像素两种误用）、999dp 胶囊，共约 20 种。最大扩散源：CardGroup 18dp（66 处调用，注释自认来自 settings-screen.jsx）；message 目录 8dp 最高频（10 处）而体系值仅 2 处。
- **方案**：定三档——卡片 14、按钮/大 CTA 15、胶囊/chip 999dp（或 CircleShape）；CardGroup 改读 token。

### S5 · pressable 按压反馈采用率极低
`pressable` 已被 45+ 处正确使用（Provider 系、NovelProjects 等），但 message 目录 **0 处**（19 个含交互文件全裸 clickable/Surface onClick）、SessionHomePage 0 处、BoardPage 0 处、ChatPage 顶栏 0 处。同屏混用三种反馈：pressable 缩放 / M3 ripple / 无反馈裸 clickable。
- **方案**：与 S3 一起做全局 sweep；同页面不允许两种反馈语言。

### S6 · mono/sans 分工未执行（设计 §3 的品牌签名失效）
规则：机器事实（模型 id、价格、token 数、时间戳、路径、URL）用 JetBrains Mono。实际：五处用系统 `FontFamily.Monospace`（Markdown.kt:2217 等 5 处、WorkspaceFilePreview:163、ChatInputSandbox:501,1135、MarkdownToAnnotatedString:425,690）；Markdown 双实现 0 处 LocalAmberType；ContextRing MetaStat 的 tok/s 用 sans（:442-448）；CouncilTimeline 模型 id 用 labelSmall sans（:1052-1058）；ChatMessageActions 时间戳/模型名 sans（:365）；CapabilityPermissions 审计行 sans（:151）；Synara 用系统 Monospace（:204）；BalanceOption 用 `bodySmall.copy(fontFamily=JetbrainsMono)` 绕过 type 体系（:99）。
- **方案**：`AmberMono` 全局替换系统 Monospace；机器事实统一走 `type.meta`。

### S7 · 页面水平边距发散
全 App 采集到 8/12/13/14/16/18/20/24/30dp 九种屏幕级边距，且同模块内部分裂：设置域四档并存（Provider 18 / CardGroup 家族 16+8=24 / 实验+首页 12 / Model 14）；council 房间页内三档（timeline 20 / composer 12 / sheet 16），气泡左缘与输入条不对齐（CouncilTimelineTab.kt:574 vs Composer:196）；BoardPage 同页三套（:372 vs :653 vs :356）；ChatPage 顶栏 20 / 时间线 16 / 底部卡片 12 三档同屏；DisplayPage 相邻区块 14dp vs 20dp 不齐（:168 vs :357）。
- **方案**：定两档——页面级 16dp、沉浸/杂志类 20dp；列表页统一行距（8dp 或 hairline 分隔，二选一）。

### S8 · 组合期副作用 / 主线程 IO / 死代码
组合期同步 IO（卡帧风险）：Novel workspace 6 处 `remember{ readXxx() }`（NovelMarkdownWorkspacePage.kt:684-685,975,991,1075,2377…）+ VM reloadState 主线程做全部文件 IO（:188-229）；WebMount UserSiteCard 组合期 cookie/凭据探测（:591-609）；SkillsPage 每个列表项组合期两次磁盘 IO（:442,453）；MiniApp shouldInterceptRequest 内 runBlocking 查库（:313,349）；QRCode 主线程逐像素画 512²（:29-40）；SettingDisplayPage 组合内直写 SharedPreferences（:290-297）；每键写盘无防抖（ModelCouncil:103-115、SubAgent:91-103）。
死代码约 1,500 行：components/ui 零引用八件套约 1,050 行（NotionListRow 124 / TagList 209 / Input 165 / TextArea 254 / RabbitLoading 35 / Greeting 36 / ViewText 237 / FloatingWindow 72）；ChatInput 尾部 ActionIconButton 块（:854-882）；ChatInputAttachments 旧 picker 块 240 行（:372-609）；OfficeProjectEditorDialog 220 行死组件（OfficePro:352-575）；NovelUi 死气泡形状+死常量（:478,200-212）；V3CapabilityIcons、quotaSupported 死分支、sandboxStatusContainerColor 裸 hex 死函数、MarkdownSplit 纯转发 scaffold、MessagePartsBlock/ChatMessage 等多处死 colorScheme 变量。
- **方案**：死代码一次性删（先跑全仓编译确认）；组合期 IO 一律改 suspend + produceState/LaunchedEffect。
