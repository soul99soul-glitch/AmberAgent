# 全面审查与修复执行计划

范围：当前 HarmonyOS 产品，HEAD 5ea51f7a 及已有未提交/未跟踪源码。基线副本见 baseline.json。

成功标准：候选问题完成独立二次核实；真实问题具备触发场景和用户影响；按依赖分阶段修复，每阶段由独立 subagent 复审；相关回归测试、完整领域测试、ArkTS lint、构建、签名通过；UI/生命周期改动在可用设备完成截图验收。未可执行的验收明确记录，不冒充通过。

约束：保护现有改动；不提交、不推送、不删除死代码；不新增无具体失败场景的重试、兜底或抽象；不使用真实付费 Provider 请求；依据当前 spec 核查 by design。

Phase 0：并行审查聊天运行/Provider、工具/搜索、小说、深读、存储/原生、UI 生命周期，以及独立 Standards / Spec 两轴。运行基线测试。
Phase 1：按二次核实结果修复数据完整性、状态与取消问题，回归测试后独立复审。
Phase 2：修复请求、工具、上下文和业务规则问题，回归测试后独立复审。
Phase 3：修复 UI / 原生及阶段复审发现的问题，独立复审。
Phase 4：扩大验证、最终交叉审查，记录问题清单、排除项、实际阶段边界和验收证据。

阶段归类会随证据调整，优先保持文件所有权独立；新增发现先核实再修。

实际收口：Phase 1 为 8 组；Phase 2 为 21 组；Phase 3 为 9 组；Phase 4 设备继续发现并核实 UI10–UI12 共 3 组（Codex 入口、跨页面 draft、Builder 表单刷新），分别窄修并独立复审。未对主题机制或共享输入组件做无关改造。
