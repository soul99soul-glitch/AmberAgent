# 小说创作流式显示与思考框修复 · 2026-10-06

本轮修复小说创作页的实时思考、实时正文和思考框滚动体验。保持已有网络、生成和持久化链路，复用 Amber 的消息行及原生流式渲染。

## 已复现的断点

同一测试服务连续发送 60 段思考与 60 段正文。旧安装包在第 3、10、17 秒的思考内容均停在第 01 段，正文要等到完成后才显示。证据见 `runtime-before/` 与 `before-thinking.jpeg`。

底层实际提供不可变的更新快照；NovelWorkspacePage 的 ForEach 保留了首次消息对象，AgentMessageRow 未按 ID 获取当前快照。Amber ChatPage 已使用当前快照访问器，本轮采用同样的绑定方式。

## 修改

- NovelWorkspacePage 的运行中消息按 ID 读取最新 activeMessages，使思考和正文实时更新，继续使用 AgentMessageRow 的流式显示。
- 快速开始仅显示实时思考，结构化 JSON 继续隐藏，完成后仍显示已保存的整理结果。
- 隐藏思考框内部与小说创作时间线的侧边滚动条。
- 思考框原有原生底部跟随、手动回看暂停、回到底部恢复逻辑未增加额外定时器；消息更新修复后已在真实界面验证这些行为。

## 验证

模拟器运行真实安装包，通过本地 OpenAI 兼容 SSE 服务接入实际 Provider → Adapter → Creation → 页面链路，未在生产代码注入模拟生成器。

- 新版第 12 秒截图显示思考第 42–51 段，思考框自动跟随新增内容，侧边滚动条不可见。
- 生成尚未结束时，第 17 秒已显示正文到第 17 段；第 22 秒增长至第 46 段，完成后第 60 段保留。见 `runtime-after/` 和正文两张截图。
- 延长思考输出到 120 段后，手动上滑回看时画面保留第 01–10 段；手动滚到底部后，第 23 秒截图持续跟随到第 93–102 段。见 `runtime-scroll-long/` 和两张手动滚动截图。
- 独立 subagent 的真实 Adapter/Creation 异步探针：讨论、正文、快速开始均在 Provider 结束前收到三段递增快照；旧快照不被原地修改。快速开始探针使用普通文本，只验证中间流式转发，最终结构解析按预期失败，不作为快速开始完整成功的证据。
- 新增回归用例在旧实现上失败，修复后小说页面及原生思考跟随相关检查 30/30 通过；完整 Harmony Node 检查 4385/4385 通过。
- 两个修改的 ArkTS 文件 lint 无缺陷；Novel 独立应用构建成功、签名验证成功；两个文件与独立构建 staging 的内容一致。
- 完成本轮改动的一次有限可维护性审查：状态仍由 activeMessages 归属，没有新增网络缓存、定时渲染或重复生成状态。
