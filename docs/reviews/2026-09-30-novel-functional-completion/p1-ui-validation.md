## 环境故障与真实边界

- 初始独立实例的 HDC serial 是 `127.0.0.1:5557`。ASCII `inputText` 返回 `No Error` 后，`dumpLayout`、`snapshot_display` 以及普通 `uptime` 都曾超时。20 秒上限后再做一次 45 秒真实截图尝试仍超时，不能把此状态判作小说 UI bug。
- 仅 stop/start 独立 `Pura 90` 一次，coldboot 保留用户数据；没有 reset、卸载、重启全局 HDC、操作真机或其他实例。
- Pura 自身 `Log/qemu.log` 证实端口在这次启动变为 `5555`；root 核实 Pura running、其他实例 stopped 后，才把脚本改到 `127.0.0.1:5555`。冷启动日志显示 OS 自身启动迟滞，约 200 秒才启动 camera/audio/wifi host，约 22:29:29 才记录 `GuestOS Boot Complete`。
- 改到已核实的当前 serial 后，首次 `dumpLayout` 再次 45 秒超时，小说 App 尚未重新启动。保留 UI gate 为 pending。
- HDC help 列出 `spawn-sub`，本机实际执行却返回 `Unknown command`；停止这条路径，没有重启或修改全局服务器。
