# 流式生成呈现：需求、架构与踩坑纪要（跨平台同源版）

> 成文于 2026-08-15，源起 iOS Chat/小说流式呈现的多轮真机打磨。目标是把这一路的需求定义、
> 架构分层、设计原则和踩过的坑沉淀成**平台无关的底层思考**——Android 要做同一套体验时，
> 按此同源设计，而不是从 UI 语法开始重新发明。
>
> 本文档是经验结晶而非任务计划；当前实现状态见 `PROJECT_STATE.md`。

## 一、需求定义（产品契约，六条）

这是用户亲口定义的规格，所有架构决策都为它们服务。任何平台的实现都要先把这六条立为验收：

1. **平滑滚动**：内容向上生长时，视口以连续速度跟随，不逐拍跳。
2. **实时 Markdown**：流式过程中始终看到排版好的格式，不是等结束才渲染。
3. **吐词节奏平滑稳定**：有缓冲层对上游速度兜底——模型慢时保底速率，模型突然变快时
   *逐渐*加速，不忽快忽慢。
4. **逐字淡入**：新文字轻盈浮现，像墨迹自然干燥。
5. **完成零跳变**：写完最后一个字，纸面纹丝不动——不重排、不跳、不闪。
   （推论：完成瞬间不得露出未渲染原文、不得切换渲染管线造成可见差分。）
6. **跟随与用户主权的平衡**：生成中自动贴底跟随；用户上滑读历史绝不拽回；
   回到近底（不是严格贴底——底部一直在跑，是移动靶）自动恢复跟随。

衍生契约（后续轮次用户补充拍板）：

- **收尾优雅**：排空末段减速到打字节奏，最后一个字以完整淡入落定——宁可排空整体长一点。
- **无分档审美**：节奏/阈值/收紧行为一律连续函数，厌恶二元分档与逐拍衰减的阶梯感。
- **运动连续性优先**：判顺滑看速度是否连续，不看快慢。

## 二、架构分层：一条管线，每层管一种物理量

```
token chunk → [积压缓冲] → [节奏器] → [增量渲染] → [淡入] → [滚动跟随] → [终态收口]
   (网络节奏)   (字数)      (字/拍)    (块/结构)   (alpha)   (pt/帧)     (零差分)
```

核心认知：**每层优化自己的物理量，而 bug 几乎全部住在层与层的换算交界处**。
这份纪要后面所有的坑，都可以归类为某个交界面的单位错配、时钟错位或所有权重叠：

| 交界 | 常见病灶 |
|---|---|
| 字符 ↔ 高度（pt） | 表格/标题的高度率尖峰，节奏器平滑了字却没平滑高度 |
| 拍间隔 ↔ 动画时长 | 固定 0.5s 淡入撞上 8ms 一拍的大积压排空，渐变堆积 |
| 节奏时钟 ↔ 布局时钟 | 排空发布快于解析，空窗露出原文 |
| 流式管线 ↔ 终态管线 | 完成切换非原子，闪原文/重排 |
| 跟随所有权 ↔ 用户触摸 | 打架或误伤 |
| 列表状态机 ↔ 滚动引擎 | 双 owner 定时器互相补刀 |

## 三、设计原则（同源，按序号引用）

- **P1 流式渲染器就是终态渲染器**。完成时零管线切换差分；终态解析落地前，
  流式渲染产物持续上屏，就绪的同一帧原子替换（"不换纸"）。
- **P2 连续优于分档**。所有随量变化的参数（时间常数、淡入时长、限频间隔、排空拍速）
  用连续函数表达。分档的边界本身就是可感知的跳变源。
- **P3「接近完成」是连续物理量**。像降落放襟翼：排空期随剩余积压连续收紧跟随时间常数
  （τ_eff = τ × allowance，allowance 从 1 衰减到 0），让欠账在最后一拍前清零，
  而不是完成瞬间一次性结账。
- **P4 平滑逼近、刚性保持**。追未到账的位移用缓动（速度连续）；已到达后环境再变
  （晚到布局）瞬时钉住，不再滑——"完成后还在滑"和"完成瞬间跳一下"是同一对矛盾的
  两个坏极端，解法是按方向区分（见坑 1）。
- **P5 用户触摸即所有权**。手指落下立刻接管（防打架）；但轻点（无拖拽位移）不构成
  离开意图，不得杀死跟随；甩向底部的惯性用速度预测提前接管（移动靶不等静止判定）。
- **P6 惟一权威所有者**。一个滚动状态机、一套近底阈值、一个终态 settle 定时器。
  双 owner 的冗余机制不是保险，是毛刺制造机。
- **P7 节奏以视觉速度为预算**。平滑的对象是 pt/帧，不是字/拍。表格行、标题、代码块
  的字→高度换算率差异巨大，纯字符预算必然在重结构内容上跳变。
- **P8 跟随用帧级驱动，绕开平台动画系统**。动画 API 的曲线/时长不可控且与布局时钟
  错相；跟随是控制回路（每帧读几何、写偏移），不是动画。

## 四、踩坑实录（症状 → 根因 → 教训 → 通用化）

按发现顺序，全部有真机/回放证据背书。

**坑 1：完成瞬间的"再滑一段"vs"单帧跳一下"**。
症状：完成后视口又滑一下（τ 缓动拖尾）→ 改成瞬时钉底 → 又变成完成那一帧跳一格。
根因：两个矛盾被混为一谈——「追赶未到账位移」与「到达后环境再变」。前者该缓动
（是书写的延续），后者该钉住（收起动画已是连续高度源，再缓动就是二次运动）。
教训：**终态收锚按方向分**：位移目标远离（新内容落地）→ 缓动追入；目标靠近
（上方内容收缩）→ 瞬时钉底。通用化：处理"完成"时先问变化来自哪个方向。

**坑 2：指数跟随的稳态滞后**。
指数平滑把离散的高度台阶抹成连续速度，代价是恒定滞后（≈0.8×每拍高度增量）。
流式期它是特性（平滑），完成时它是毒药（钉底一帧清掉滞后=跳变）。
教训：滞后必须在完成前连续清零（P3），完成事件本身不该承担清账。

**坑 3：容差边界极限环**。
指数尾段每拍步长低于到达容差后，位移在容差边界两侧徘徊，永远不满足严格小于判定，
终态所有权永不交还。教训：**任何"步长小于 ε 就收口"的分支都要同时限定总量**
（如 ≤ 数 pt），否则退化路径上会吞掉任意大的位移。

**坑 4：dt≈0 退化路径**。
帧回调以通用模式注册时会同帧双发且时间戳相同（dt=0），此时"步长=0<容差"的判定
会让任意大的剩余位移被单帧清零——坑 1 刚修好的跳变在退化路径复发。
教训：**凡依赖 dt 的分支，都要问 dt 异常（0、负、同帧重入）时行为是什么**。

**坑 5：排空恒速砸尾**。
完成时积压一次定锚、整轮恒速——大积压中段 whoosh 很爽，但末尾仍以 1500 字/拍砸
到底，"字没逐字出来就成批冒出"。教训：**收尾必须减速**——拍速随剩余积压连续收敛
（min(锚速, max(保底, 剩余/N))），末拍回到打字节奏，配合淡入机制让最后几个字以
完整淡入落定。定锚只该是速度*上限*，不是整轮速度。

**坑 6：实例哈希对象进缓存键**。
动态色（iOS UIColor）的 hash 是实例身份哈希——两次构建配置实例哈希必不同，渲染缓存
全落空，完成瞬间前缀全部 miss → 已显示块退占位帧。教训：**缓存键只用值语义稳定的
输入**（标量、按固定 trait 解析后的颜色分量、值相等即哈希相等的对象）。通用化到
Android 同样成立：任何"每次构造产生新实例"的对象（某些 Painter/Brush 包装）都别进键。

**坑 7：管线切换非原子，闪未渲染原文**。
完成瞬间一个布尔标志（动画开关）翻转，让三条缓存路径同时拒绝流式渲染产物，
气泡兜底到纯文本——整段 markdown 原文可见几帧，再重排（用户逐帧录像实锤）。
教训：**P1 的完整含义**——不仅"同一个渲染器"，还要"缓存命中条件跨流式/终态稳定"：
视觉等价的判定只能基于视觉输入（视觉哈希），绝不能包含随生命周期翻转的执行模式标志。

**坑 8：表格半行的结构性差分**。
流式期把"最后一行"从解析里剔除（防半行先冒出来再重组成行），完成时参数翻转、
全文重新分块——最后一行成批出现 +36pt、表格重建。教训：**消除差分的方向是让流式
期就渲染"部分形态"**（缺单元格补空渲染），而不是隐藏到结束。隐藏只是把跳变推迟
到最后一刻并放大。无管道的歧义尾行仍需消费不渲染（防文本↔表格行互变），这是
结构歧义的本质代价，不是实现缺陷。

**坑 9：结构闭合的回溯变形**。
`**` 闭合那一拍，字面星号变粗体、字形宽度变化、整段重新换行。这是上游输出结构化
文本的物理极限（吐的是结构不是笔画）。教训：接受为已知语义，或把闭合提前到流式期
（让变形发生在书写中而非书写结束）；**绝不要留到完成瞬间**（那就成了坑 7/8）。

**坑 10：固定淡入时长撞上变速节拍**。
0.5s 淡入 × 8ms 一拍 = 60+ 条并发渐变拖着长尾巴，性能与观感双输。教训：**淡入时长
随本拍字数连续缩放**（时长×字数 ≈ 常数），系统负载与生成速率解耦；末拍字少时
自动回到完整淡入——和坑 5 的减速收尾天然组合成"优雅收笔"。

**坑 11：touch-down 即暂停的误伤**。
手指落下立刻暂停跟随是对的（防内容在指尖下移动），但纯轻点（从未拖拽）在快速生成
中，按下那零点几秒底部就跑出恢复阈值——松手判定失败，跟随静默死亡。
教训：**恢复判定要区分"用户意图"与"几何碰巧"**：记录按下时是否在跟随、期间是否
真的拖拽过；轻点=恢复（即使几何已超阈），拖拽=交给几何判定。

**坑 12：移动靶不等静止判定**。
甩向底部的惯性，等减速静止再判"是否近底"，底部早就跑出窗口——用户被迫甩第二次。
教训：释放瞬间用触控速度预测落点（速度×减速时长的近似即可，无需精确），预测命中
容差就用一次短动画磁吸接管。注意 Reduce Motion 用户跳过磁吸走自然减速。

**坑 13：双 owner 的冗余定时器**。
驱动引擎已负责终态收锚（逐帧钉底+静默交还），视图层还留着旧机制的 0.4s 定时器，
完成 0.4 秒后多余地再动一下。教训：P6。重构时"新旧机制并存当保险"的过渡态，
收尾时必须删干净，否则它会在最安静的时刻提醒你它存在。

**坑 14：字符预算的高度尖峰**（未完全修）。
节奏器按字预算（36 字/拍），但 36 字表格 ≈ 数百 pt，36 字正文 ≈ 50pt——重结构内容
上高度率尖峰仍会硌一下。正解是 pt 预算（按尾块当前行高换算）。本仓思考框内部滚动
已用 540pt/s 的 pt 限速做先例。做 Android 时直接从 pt 预算起步，别重走字符预算的弯路。

**坑 15：感知不可信，取证裁决**。
"完成振动关不掉"追了两天，最终日志裁决：app 零触发，振动来自恰好撞上完成时刻的
外部通知（静音模式不静振动）。教训：**用户感知报告先立取证 canary（一行日志），
用运行时证据裁决，再动代码**。这条对 Android 一样：振动/卡顿/"感觉变了"类报告，
先 `adb logcat` 裁决再修。

## 五、验收与测试策略（跨平台同构）

1. **回放契约测试走真实组装链**：挂生产视图树（真窗口）、真实滚动容器、公开输入面
   驱动（信号+消息流），断言取自底层容器几何。绕过组装链的单元测试再绿也不算数
   （本仓三次"全绿但生产不可达"的教训）。
2. **红测试先行**：复现形态 → 定契约断言（红）→ 修 → 绿。修完的契约永久留作回归锁。
3. **断言连续性，不只断终态**：帧间位移上限、单调收敛、无回跳、视图 identity 保持、
   高度变化 ≤0.5pt、窗口内不出现"未渲染原文帧"。终态断言会漏掉所有中间帧的病。
4. **帧级探针**：display link/帧回调逐帧采样偏移+高度+关键视图 identity，别用
   asyncAfter 延迟采样（会恰好漏掉瞬态——本仓真实发生过）。
5. **模拟器绿 ≠ 真机**：性能探针在模拟器上负载敏感（同二进制 39~119ms 波动），
   手感问题的最终裁决是真机逐帧录像。CI 性能门禁设为护栏而非真相。

## 六、Android 映射（同源落点）

同一套管线与原则在 Android 的对应物，按层给：

| 层 | iOS 现实现 | Android 同源落点 |
|---|---|---|
| 节奏器 | `StreamPresentationPacingPolicy`（**已在 KMP commonMain**，双端共用） | 直接复用 KMP；UI 侧只接 backlog 信号 |
| 积压缓冲 | coordinator 内 accumulator + backlog 计数 | 同构；注意 ChunkStream 背压 |
| 增量渲染 | 块解析 + TextKit 增量 append + 前缀缓存 | Compose：`MarkdownText` 分块 + `AnnotatedString` 前缀复用；View：spans 增量 append；**同样按块缓存、前缀命中** |
| 淡入 | 尾段整体 alpha（时长随拍字数缩放） | `graphicsLayer { alpha }` 帧回调驱动；Compose Text 无逐段 alpha 时退化为尾块整体透明度 |
| 滚动跟随 | CADisplayLink 直写 contentOffset | `Choreographer`/`withFrameNanos` 直写 `scrollBy`/`ScrollState.dispatchRawDelta`；**不要**用 `animateScrollTo`（曲线不可控=坑 1 前传） |
| 终态收口 | 方向性收锚（增长缓动/收缩钉底）+ P3 收紧 | 同一状态机语义照搬；Compose 的 `LazyList` 远端 item 重建是坑 6/7 的高发区，键要用稳定内容键 |
| 近底判定 | 滞回阈值 + 速度预测磁吸 | `canScrollForward`/首末项可见性 + `flingVelocity` 预测；`onDragStopped` 拿速度 |

Android 特别注意三条（iOS 已付过学费）：
- **倒序列表**（`reverseLayout=true`）让贴底跟随免费——RN 生态的通行解。若 Compose
  迁移动过倒序念头，评估 Markdown 流式重排与倒序的相互作用后再动。
- **配置缓存键**：Compose 的重组天然高频重建配置对象，坑 6（实例哈希）在 Android
  只会更容易发生——`remember(key=…)` 的 key 用值稳定的输入。
- ** kav 故障面**：Android 有帧率自适应（120Hz 桌面模式），坑 4 的 dt 异常在
  帧率切换瞬间高发，帧驱动代码从第一天就要处理。

## 七、需求方的审美决策存档（争议时回看）

这些是用户在本轮明确拍板的取向，后续任何人（含 AI）优化手感时不得违背：

1. 看运动连续性，不看速度绝对值。
2. 不要二元分档、不要逐拍衰减的阶梯感——一切随量连续。
3. 写完即静止：纸面部分零变化；允许变化的只有"纸外家具"（键盘/建议条/思考卡），
   且必须做 ramp。
4. 收尾宁慢勿砸：最后一个字必须优雅地逐字淡入结束。
5. 墨随字速干：淡入快慢跟随节奏，但收笔必是完整淡入。
6. 简洁机制优于堆机制：修复一律"把离散特判换成连续函数"，不新增状态机/特判层。
