# Android UI 精修实验计划

日期：2026-09-12。分支：`codex/ui-refinement`，基线：`d752f90`。交付工作树：`/Users/arquiel/Downloads/AI/AmberAgent/android-ui-refinement`（实施期间为`/private/tmp/amber-android-ui`）。创建分支时 main 的未完成合并不纳入本次基线；其他任务随后推进 main 不会自动并入本实验。用户授权自主选择原型方案、分阶段实施并在每阶段进行独立 review。

## 目标与取舍

目标是完整 Android 产品的一致性和细节精度：保留 terminal × 暖石墨、mono/sans 分工、克制的 accent、已有流式渲染与动效；改善页面层级、行组、边距、控件布局和可读性。原型是视觉参考，现有 Android 的真实功能和状态链是行为依据。

已审阅原型首页、设置、聊天、服务商、看板、小说截图，见 `reference/`；其余页面在对应阶段继续对照。

吸纳：16dp 页面基线、14dp 统一行组、15dp 主按钮、52/64dp 最小行高、32dp 中性图标底座、清楚的标题与机器信息、单 accent 状态、带文字的创建入口、首页继续区与功能入口的关联。

调整：原型 40px 点击区域按 Android 控件实际布局提供至少 48dp；行高用 minimum 而非固定高度；小字对比度优先于原型灰度；有意义的说明、状态与错误反馈保留；大字体下，操作标签、说明和表单允许换行或横向滚动；首页会话标题/消息摘要、技能列表摘要保留省略，完整内容在详情展示。小应用标题独占两行宽度，超长名称仍可省略。这是为了保持列表浏览效率而有意偏离原型“全部不截断”的规则。列表底部为 FAB 和系统手势留空间。原型 DESIGN 的 R6 五色瓦片与 HANDOFF 的 R7 回拨冲突时，采纳后者的中性瓦片与单 accent。

不照搬：全屏点纹、到处使用点阵字标、五色分类瓦片、强制阅读纸面永远浅色、把所有字体硬压为 UI 字阶、删除原型未覆盖路由、拆分 ViewModel/引入统一控制器等无关架构重构。点纹只考虑首页/空态，正文保持安静。

## 分阶段实施

每阶段：实现 → 编译/最小定点验证 → subagent 独立检查调用链与 UI 边界 → 修复有效问题 → 记录验收后再进入下一阶段。主代理串行运行构建、集中进行界面观察；worker 按文件独占，不覆盖他人改动。

| Phase | 范围 | 可验证验收 |
|---|---|---|
| 0 · 基线与设计决策 | 原型捕获、报告误报复核、隔离分支、完整计划、构建和设备路径 | 清洁实验工作树无合并标记；基线编译；独立计划 review |
| 1 · 视觉底座 | 现有 AmberTokens/AmberType、M3 与 Workspace 色板桥接、共享顶栏、CardGroup、实验设置公共组件 | 深/浅/Sage/AMOLED 和 accent 一致；语义错误色独立；52/64 最小行高、大字体不截断；不改持久化契约 |
| 2 · 入口与设置 | 会话首页、设置首页/显示/服务商/模型，搜索/资料/收藏等入口列表 | 所有原入口保留；主操作清楚、分组边距一致；长名称和 trailing 控件同时可见；筛选/选择/导航不变 |
| 3 · 聊天与消息 | 聊天外壳、输入/附件、工具/推理/审批/媒体、Markdown 及报告中已确认行为缺陷 | 发送/取消/附件/审批接线不变；流式动画保留；触控布局无互相遮挡；导出、段落/列表行为定点验证 |
| 4 · 工作台与其余页面 | 看板/阅读、小说、议会、技能/扩展、小应用、同步备份、日志/历史/live 等 | 对照各类页面的共用语言；保留真实状态/错误/权限反馈；底部、键盘、长标题、大字体布局闭合；不为风格重写业务层 |
| 5 · 产品验收 | 跨页面真实导航、主题切换、窄屏/大字体、最终独立源码与视觉 review | 产出可运行的隔离 APK；截图与缺陷闭环记录；必要测试/编译通过；未验证的 provider/账户/设备边界如实列明 |

## QA 清单

- 主题：暖石墨深/浅；Sage 深/浅；AMOLED 黑底；切换 accent 的按钮前景和选中态。
- 布局：普通手机宽度、窄屏、系统放大字体；顶栏返回与操作不挤压标题；列表长文案与尾部状态共存；弹窗与输入法、底部手势/FAB 不遮挡最后项。
- 路由：主页→聊天/设置/看板/小说/议会/扩展/小应用/WebMount/资料/搜索/收藏；设置→显示/服务商/模型/备份，关于页长按→Debug；通知/分享外部入口与各入口返回链。逐Screen清单见 `ROUTES.md`，不因原型未覆盖而判死路由。议会创建保留先落库、失败清理、成功后导航的owner顺序。
- 交互：主题持久化、筛选、模型选择、表单保存、关闭/返回、聊天输入/附件/取消/审批的原 owner 回调；危险动作不以测试名义触发真实用户数据删除。
- 性能：不在逐帧绘制中构建大对象；不加列表全屏纹理动画；不改 Markdown 流式状态机、缓存和 reveal 机制。
- 测试：复用现有覆盖；只为确认的行为变化或高风险主题边界添加最低必要测试，不创建截图框架，不测试源码字符串。
